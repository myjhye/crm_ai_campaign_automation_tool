# AI-C — 캠페인 정책 검수 도구 연결

## 구현 범위

AI 어시스턴트에서 작성 중인 캠페인을 선택하고 정책 검수를 요청할 수 있다. 모델은 `validate_campaign` 도구만 선택하며, 대상 계산과 제외·차단 판정은 단계 8의 `services/policies.py`를 그대로 호출한다. 결과 카드는 최초 대상, 제외, 승인 대상, 사유별 인원, 캠페인 전체 차단 사유와 검수 만료 시각을 표시한다.

AI는 검수 기록까지만 만든다. 캠페인은 `DRAFT`에 머물며 승인 요청·승인·반려·모의 발송 도구는 제공하지 않는다. 방문자는 결과 카드의 **캠페인 승인 화면 열기**로 이동해 단계 8 화면에서 직접 결정한다.

## 처리 흐름

1. AI 화면은 선택한 데이터셋의 `DRAFT` 캠페인만 검수 목록에 표시한다.
2. 브라우저는 선택한 캠페인 ID와 현재 version을 `/api/v1/ai/chat`에 서버 컨텍스트로 보낸다.
3. 서버는 모델 호출 전에 캠페인의 데이터셋·상태·version을 확인한다.
4. provider에는 캠페인 이름·채널·상태·version만 전달하고 인자가 없는 strict `validate_campaign` 도구 하나만 허용한다.
5. 서버가 도구 이름과 빈 인자를 검증한 뒤 단계 8 검수 서비스를 `actor_type=AI`로 실행한다.
6. 검수 대상 고객 스냅샷과 감사 이력을 같은 트랜잭션에 저장하고 구조화 결과를 AI 카드로 반환한다.

모델에는 고객 행, 연락처, 대상자별 제외 사유가 전달되지 않는다. 검수 숫자는 모델이 생성하지 않고 PostgreSQL에 저장된 정책 결과를 그대로 렌더링한다. 데이터셋이 바뀌거나 캠페인 version이 오래되었거나 상태가 `DRAFT`가 아니면 실행을 거절한다.

## 구현 위치

| 파일 | 역할 |
| --- | --- |
| `app/ai/tools.py` | 인자 없는 strict `validate_campaign` 계약 |
| `app/ai/provider.py` | 선택 캠페인 컨텍스트에서 검수 도구만 허용 |
| `app/ai/orchestrator.py` | 리소스 확인, 정책 서비스 호출, AI 실행 로그 |
| `app/services/policies.py` | 수동·AI가 공유하는 검수 트랜잭션과 감사 주체 기록 |
| `frontend/src/features/ai/index.js` | 캠페인 선택, 검수 결과 카드, 승인 화면 이동 |

## 검증

통합 테스트는 AI 검수 결과의 인원 등식, 실제 `validation_runs` 저장, 감사 주체 `AI`, 캠페인 상태 `DRAFT` 유지, 승인 행 미생성을 확인한다. 브라우저 테스트는 캠페인 ID·version 전달, 사유별 인원 카드, 승인 화면 이동을 확인한다. 로컬 검증에서 PostgreSQL 전체 107개, JavaScript 단위 15개, Chromium E2E 15개가 통과했다. 다음 단계는 승인된 스냅샷을 사용해 중복 없이 실행하는 단계 9 모의 발송이다.
