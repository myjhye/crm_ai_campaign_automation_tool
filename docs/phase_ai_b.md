# AI-B — 캠페인 초안·A/B 카피 제안과 확인 적용

## 사용 방법

Campaigns 오른쪽 어시스턴트는 **전체 초안 생성만 제공**한다. 대상·목표·채널·공통 말투·KPI·A/B 강조점을 선택하고 혜택과 KPI 목표값을 입력한 뒤 **전체 초안 만들기**를 누른다. 메인 폼을 미리 작성하거나 추가 문장을 입력할 필요는 없다.

목표·공통 말투·A/B 강조점은 목록 마지막의 **기타 (직접 입력)**를 선택할 수 있다. 선택하면 해당 그룹 아래 입력란이 열리고, 다른 옵션으로 전환하면 숨겨지며 직접 입력한 내용은 보존한다. ‘기타’를 선택한 채 비워두면 생성하지 않는다. 목표는 최대 500자, 말투·강조점은 각각 200자다. 채널·KPI·저장된 대상은 실제 지원하는 값만 선택한다.

이름은 대상 이름과 목표를 조합하고 AI는 확정된 설정으로 카피를 작성한다. 생성 성공 시 별도 확인 없이 메인 폼에 자동 입력하며, 버튼 아래 완료 알림을 4초 표시한다. 오류는 자동으로 숨기지 않는다. 문안을 검토한 뒤 **초안 저장 후 확인**으로 저장한다. 초기화는 폼을 비우며 저장된 캠페인을 삭제하지 않는다.

기본 추천은 재구매 유도·이메일·다정한 말투·전환율 5%·혜택 강조 대 관계 강조, 비율 50:50이다. 제외 조건·예정일·만료일은 기존 폼 값을 유지한다. 브랜드 톤은 메인 폼에 노출하지 않고 생성 설정과 기존 저장값을 유지한다. 필수값·서로 다른 강조점·KPI 범위는 브라우저와 서버에서 검증한다. mock/live 모두 설정 기반 생성을 지원하며, API 장애나 출력 검증 실패 시 기존 폼을 유지한다.

`POST /api/v1/ai/campaign-plan`의 `campaign_setup`은 확정된 선택값이다. 서버가 같은 데이터셋의 보관되지 않은 최신 revision을 확인하고 기존 카피 검증 서비스를 직접 호출한다. 외부 호출 중 DB 트랜잭션을 유지하지 않는다. 이전 자유 문장 API 경로는 호환 목적으로 남아 있지만 현재 화면에서는 사용하지 않는다.

일반 AI 채팅은 지표·세그먼트 조회용으로 유지한다. 생성 중에는 메인 폼을 잠그며 실패하면 기존 문안을 유지한다. 화면 이동 시 요청을 취소하고 입력 내용이 달라졌으면 자동 채우기를 중단한다. 모의 모드도 같은 화면을 사용하며 모의 응답임을 표시한다.

## 동일 설정의 결과 재사용

`005b` 마이그레이션의 `ai_copy_cache`에 검증된 카피를 보관한다. 키에는 데이터셋·원천 데이터 버전·세그먼트 revision·생성 조건·기타 입력·추가 요청·집계 프로파일·정책·모델·프롬프트 버전·출력 제한이 포함된다. 조건이 같으면 서버 재시작 후에도 같은 문안을 반환하고 LLM을 호출하지 않는다. 화면에는 ‘같은 설정의 이전 초안을 불러왔습니다’ 알림을 표시한다.

성공 결과만 저장하며 재사용 전에도 검증한다. 오류는 캐시하지 않는다. 설정이나 대상 데이터가 바뀌면 새 키로 생성한다. 프롬프트 변경 시 `CAMPAIGN_PROMPT_VERSION`을 올려 기존 결과와 구분한다. 캐시에는 원문 프롬프트 대신 키 hash와 생성 결과만 보관한다. 자동 만료는 없으며 데이터셋 삭제 시 함께 삭제된다.

캐시는 카피만 재사용한다. 제안 ID·30분 만료·현재 데이터 버전은 매 요청 새로 만들고 확인 저장 규칙을 유지한다. 동시 최초 요청은 모델을 각각 호출할 수 있지만 DB에 먼저 저장된 결과를 공통 반환한다. 이미 완료된 같은 키의 후속 요청은 모델 토큰을 사용하지 않는다. 외부 호출 대기 중 DB 트랜잭션을 유지하지 않는다.

## 구현 구조

| 위치 | 역할 |
| --- | --- |
| `app/ai/campaigns.py` | 입력 기준·프로파일 준비, 카피 검증, 제안 생성·수정·적용 |
| `app/ai/tools.py` | create_campaign_draft / generate_copy strict 도구 |
| `app/ai/provider.py` | 기존 실제/모의 provider에 캠페인 호출 추가 |
| `app/ai/orchestrator.py` | 기존 chat·confirm 경로에 캠페인 제안 연결 |
| `alembic/versions/005a_ai_campaign_proposals.py` | 제안 종류·캠페인 FK·데이터/정책 버전 |
| `frontend/src/features/campaigns/ai.js` | 오른쪽 AI 입력·생성·실패 처리 |
| `frontend/src/features/campaigns/index.js` | 메인 폼 조건 전달·A/B 자동 채우기·일반 저장 |

현재 UI는 `/ai/campaign-draft`로 생성한다. 이 API가 보관하는 제안 레코드는 유지하지만 화면에서 제안 confirm API를 호출하지 않는다. 자동 채우기는 브라우저 입력값만 변경하고, 최종 저장은 일반 캠페인 POST/PUT과 버전 검사를 사용한다. 아래 제안 수정·확인 보장은 유지된 백엔드 API의 계약이다.

기존 `/api/v1/ai/chat`에 `campaign_brief` 또는 `campaign_id`·`campaign_version`을 추가한다. 별도 `/api/v1/ai/campaign-draft`, `/api/v1/ai/copy-variants`도 같은 서비스를 호출한다. `POST /ai/actions/{id}/revise`는 방문자가 편집한 문안으로 새로운 제안 ID와 hash를 만들며, 이전 카드는 만료한다. 확인 API는 수정 payload를 직접 받지 않는다.

## 보장과 범위

- 새 초안의 대상 revision·채널·혜택·목표는 방문자가 지정한다. AI는 A/B 카피·가설·생성 근거만 만든다. 새 초안 비율 기본값은 50:50이다.
- 기존 카피 변경은 대상·제외 조건·혜택·쿠폰 만료·예정 시각·KPI·비율을 서버 원본에서 가져온다. 모델이 바꾸지 못한다.
- 모델에는 고객 행 대신 최소 집단 기준을 적용한 프로파일과 입력 조건·카피 정책을 제공한다. DB 트랜잭션은 모델 호출 전에 종료한다.
- 모델 출력은 단계 7의 일반 텍스트·채널 길이·필수 카피·비율 검증을 다시 통과한다. 생성 본문에 혜택 원문을 요구하고 입력 혜택·만료에 없는 숫자 표현은 거절한다. 모든 비수치 사실의 진위를 자동 검증한다는 의미는 아니므로 방문자가 결과를 검토한다.
- 방문자 직접 편집은 단계 7의 일반 입력 규칙을 적용한다. 수정 시 만료 시각·기준 버전은 연장하거나 갱신하지 않는다.
- 제안 생성은 업무 캠페인을 저장하지 않는다. 확인 시 데이터셋·hash·30분 만료·데이터/정책 버전·기존 캠페인 version/DRAFT를 확인한다.
- 캠페인 변경·감사 이력·제안 적용 표시는 같은 트랜잭션이다. 중복 확인은 기존 결과를 반환한다. 실패한 감사 기록은 업무 변경도 롤백한다.
- AI 실행 로그는 provider/model·도구·상태·소요 시간·토큰·prompt version을 기록하며 원문 프롬프트는 저장하지 않는다.

브랜드 톤은 방문자가 지정하는 입력값이다. Settings의 영속 정책·브랜드 가이드 편집, 대상자 검수·승인·발송은 후속 단계에 남아 있다. 새 초안의 제외 조건·예정 시각은 저장 후 Campaigns에서 편집할 수 있다.

도구 계약은 [OpenAI Function calling 공식 문서](https://developers.openai.com/api/docs/guides/function-calling)의 strict 속성 규칙을 따른다. 기존 모델 설정과 timeout·출력 제한을 유지한다.

## 실행과 검증

기타 직접 입력과 캐시 추가 후 AI-B PostgreSQL 통합 테스트 10개, 빈 DB·증분 마이그레이션 테스트 1개, 캠페인 브라우저 테스트 2개를 통과했다. 동일 요청의 provider 호출 횟수 유지·같은 카피 반환·독립 제안 ID·캐시 적중 시 토큰 0, 기타 내용·데이터 버전·프롬프트 버전 변경 시 재생성을 검증했다. 로컬 DB는 `005b`까지 적용했고 Alembic 모델 차이가 없음을 확인했다.

카피 작성 instructions에 고객 관점의 짧은 문장, 채널별 권장 분량, 공통 톤과 A/B 강조점 분리, 고객 문구와 내부 가설 분리, 상투어 편집 원칙과 이메일 예시를 추가했다. 예시에는 임의 마감을 넣지 않으며 실제 혜택과 다른 예시 숫자를 복사하지 않도록 명시한다. 서버의 혜택 원문·숫자·채널 정책 검증은 변경하지 않았다. 합성 입력의 실제 이메일 생성 2회에서 기존 검증을 통과했고, 가설이 별도 필드에 분리되고 A는 혜택·B는 안부로 시작하는 것을 확인했다. 첫 생성에서 남은 ‘준비했어요’ 표현은 후속 편집 지침으로 보완했다. 이는 소수 샘플 점검이며 모든 생성물의 문체 품질을 보장하는 평가는 아니다.

만료일은 UTC 숫자 조각과 비교하지 않고 Asia/Seoul의 날짜 전체로 검증한다. 예를 들어 `2026-09-30T13:26:00Z`는 `2026년 9월 30일 22:26`으로 모델에 제공한다. 날짜의 일부 숫자가 임의 할인액·기간을 허용하는 근거가 되지 않도록 분리했다. `15% 할인 쿠폰`, 한국 시간 9월 30일 22:26 만료 조건으로 실제 provider의 A/B 생성·검증을 1회차에 통과했다. 이 확인은 빈 프로파일과 기본 카피 요청을 사용했고 업무 캠페인은 저장하지 않았다. 날짜·단위 회귀 테스트와 provider 단위 테스트 6개를 통과했다.

카피 검증은 숫자 천 단위 쉼표와 공백 차이를 정규화한다. 금액·단위 변경은 계속 거절한다. 출력 검증 실패 시 서버의 오류 사유를 전달해 한 번만 재생성하며, 다시 실패하면 혜택 누락·허용되지 않은 숫자·채널 정책 등 사유를 구분해 표시한다. 생성 원문을 로그에 남기지는 않는다. 자동 재생성이 발생하면 모델 호출 시간과 토큰 비용이 추가된다.

사이드바 전환 후 JavaScript 단위 15개, 브라우저 E2E 14개, provider 단위 3개를 통과했다. 브라우저 API 대역으로 A/B 자동 입력, 기존 비율 유지, 생성 시 업무 저장 없음, 실패 시 입력 유지, 일반 저장 버튼 동작과 챗봇 설정 제거를 검증했다.

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

로컬 DB에 `005a`를 적용했다. 전체 백엔드 93개 통과 후 제안 수정 테스트를 추가하여 AI-B 통합 테스트 6개를 통과했다. 브라우저 E2E 14개도 통과했다. 테스트는 동시 확인, 오래된 카피 제안, 임의 숫자 혜택 거절, 만료, 감사 실패 롤백, 3채널 생성, 수정 제안의 새 hash와 이전 카드 만료를 포함한다.

실제 API에서도 한국어 혜택 원문을 유지하는 A/B 두 안의 제안 생성을 확인했다. 영어 혜택을 임의 번역한 응답은 검증에서 거절되는 것을 확인했다. 실제 호출 검증에서는 업무 캠페인을 저장하지 않았으며, 확인 저장의 원자성은 격리 PostgreSQL 통합 테스트로 검증했다.
