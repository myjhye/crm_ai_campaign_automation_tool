# CRM 지표와 기준 시점 — 단계 0

이 문서는 계산 계약이다. 고객 상태·경과일·비율·기간 유틸리티는 구현되었으며 DB 집계·대시보드·캠페인 기여 쿼리는 이후 단계에서 구현한다.

## 시간과 고객 상태

- 모든 계산은 명시적 reference_at을 기준으로 한다. 원천의 발생 시각과 적재 시각을 구분하며 적재 시각으로 구매 기간을 판단하지 않는다.
- 구매 원천 조회는 기준 시점 이하의 유효 완료 주문만 선택한다. 미래 주문을 포함한 최신 구매값을 과거 계산에 사용하지 않는다. 순수 계산 함수는 미래 구매값이 넘어오면 오류를 발생시켜 잘못된 조회를 드러낸다.
- 미구매 고객의 days_since_last_purchase는 null이다. `GTE 60` 조건에는 null이 포함되지 않는다.
- 경과일은 UTC 시각 차이의 완전한 24시간 수다. 29일 23시간 59분은 29일이다. 화면의 달력 날짜 차이로 대체하지 않는다.
- 고객 상태는 기준 시점에 탈퇴했으면 WITHDRAWN이 우선이다. 미래 탈퇴는 과거 상태에 영향을 주지 않는다. 가입 이전 기준 시점은 고객을 집계에서 제외하며 계산 함수 직접 호출은 오류다.

| 경과일 | 구매 고객 기준 | 미구매 고객 기준 | 상태 |
| --- | --- | --- | --- |
| 0~29 | 마지막 구매 후 | 가입 후 | ACTIVE |
| 30~59 | 마지막 구매 후 | 가입 후 | CHURN_RISK |
| 60 이상 | 마지막 구매 후 | 가입 후 | DORMANT |

예: 가입한 지 100일인 고객이 29일 전에 구매했으면 ACTIVE, 30일 전이면 CHURN_RISK, 60일 전이면 DORMANT다. 구매 없는 가입 60일 고객은 DORMANT지만 구매 경과일은 null이다.

## Overview 계약

| 지표 | 정의 |
| --- | --- |
| 전체 고객 | signup_at < to인 distinct 고객, 탈퇴 고객 포함 |
| 신규 고객 | [from,to)에 가입한 distinct 고객 |
| 활성 고객 | 기간 내 VIEW/CART/PURCHASE 중 하나 이상 발생한 distinct 고객 |
| 휴면 고객 | to 시점의 DORMANT 고객, signup_at < to 대상 |
| 구매 전환율 | 기간 내 구매한 활성 고객 / 기간 내 활성 고객 × 100 |
| 재구매율 | 기간 내 완료 주문 2건 이상 고객 / 기간 내 완료 주문 고객 × 100 |
| CRM 기여 매출 | 아래 귀속 규칙에 따른 완료 주문액 합계 |

활성 고객 KPI와 고객 상태 ACTIVE는 다른 개념이다. 이벤트 KPI는 당시 발생한 이벤트를 집계하므로 이후 탈퇴해도 역사적 수치에서 제거하지 않는다. 상태 분포는 조회 시점의 상태를 사용한다. PURCHASE 이벤트와 orders를 매출에 중복 가산하지 않는다.

퍼널은 기간 내 VIEW→CART→PURCHASE 순서를 만족하는 distinct 고객 수다. 동일 고객의 반복 이벤트를 중복 인원으로 세지 않는다. 이전 기간은 같은 길이의 직전 구간이며 비율 차이는 %p, 상대 변화는 %로 표시한다. 이전 값이 0이면 상대 변화는 null로 표시한다.

## 캠페인 성과 계약

| 지표 | 정의 |
| --- | --- |
| 오픈율 | 오픈 고객 / 전달 성공 고객 × 100 |
| 클릭률 | 클릭 고객 / 전달 성공 고객 × 100 |
| CTOR | 클릭 고객 / 오픈 고객 × 100 |
| 전환율 | 귀속된 구매 고객 / 전달 성공 고객 × 100 |
| 고객당 매출 | 귀속 매출 / 전달 성공 고객 |

오픈율·클릭률·전환율은 동일 발송 cohort와 관찰 기간의 distinct 고객을 사용한다. CTOR에서 클릭 고객이 오픈 고객보다 많은 데이터는 데이터 품질 오류로 분리하며 100%로 임의 보정하지 않는다. 공통 percentage는 분자가 분모를 초과하는 입력을 거절한다.

주문 시각 이전 7일 이내의 마지막 유효 클릭에 주문을 한 번만 귀속한다. 경계는 `주문시각-7일 <= 클릭시각 <= 주문시각`, 동일 시각 클릭은 이벤트 ID로 결정한다. 클릭이 없으면 CRM 기여 매출에 포함하지 않는다. 취소·전액 환불은 제외하고 부분 환불은 MVP에서 미지원이다.

분모 0은 null/NO_DENOMINATOR, 미구현 집계는 not_ready, 채널 미지원 지표는 not_applicable로 구분한다. A/B의 관찰 미종료·표본 부족은 판단 보류다. 무발송 통제군 없는 증분 지표는 not_available이다. 모의 데이터와 업로드 데이터는 dataset·source로 구분한다.

### A/B 판단 가정

비율형 주지표의 95% 신뢰구간은 Wilson score interval을 사용한다. A/B 차이는 pooled two-proportion z-test의 양측 p-value로 확인하며 유의수준은 5%다. 이론상 필요 표본은 A안 관측률(분모가 없으면 5%) 대비 50% 상대 개선, 검정력 80%, 양측 유의수준 5%를 가정해 산출하고 화면에 함께 표시한다. 300명 합성 데이터로 판단 경로를 시연하기 위한 실행 최소 표본은 안별 30명이다. 승자 선언에는 이 기준과 별개로 기존 `p < 0.05`를 반드시 만족해야 한다. 이 시연 기준은 실제 서비스의 사전 표본 설계를 대체하지 않는다.

실험 관찰 종료는 포트폴리오 시연용으로 발송 완료 즉시(`0일`)다. 매출 귀속 창 7일과 실험 판단 관찰 기간은 별도 값이다. 실제 서비스에서는 상품의 구매 주기에 맞춰 더 긴 관찰 기간을 사전에 고정해야 한다. 안별 최소 표본 미달, B안 수신거부율이 A안보다 1%p 넘게 높음, 유의한 차이 없음 중 하나라도 해당하면 `HOLD`다. `click_rate`는 클릭 고객, `conversion_rate`는 귀속 구매 고객을 성공으로 센다. 연속형 매출의 분산을 이용한 검정은 지원하지 않으므로 `revenue`가 주지표면 판단 보류한다. 기준군 비율이 0이면 상대 개선율은 null이다.

## 검증 근거

단계 5 조회는 `reference_at=to`이며 배타적 상한에 맞춰 `purchased_at < to`인 완료 주문을 사용한다. 고정 시점 이하를 보관하는 단계 3 캐시와 달리 원천을 다시 계산하며 캐시를 변경하지 않는다. 활성 고객은 상태 ACTIVE와 별개다. 구매 전환율의 분자는 기간 내 구매한 활성 고객, 재구매율은 기간 내 완료 주문 기준이다. 순서형 퍼널은 `VIEW 시각 < CART 시각 < PURCHASE 시각`이며 같은 시각은 다음 단계로 세지 않는다.

고정 RFM `rfm-fixed-v1`, 현재 채널 상태와 과거 기간의 구분, 취소·환불 처리, 이전 기간 및 %p 비교는 [단계 5 실행 안내](phase_5_customer_analytics.md)에 정의했다. 고객 및 대시보드는 같은 데이터 버전을 요구할 수 있고 버전 충돌은 409로 반환한다.

`tests/unit/test_phase_zero.py`에서 29/30/59/60일, 미구매·탈퇴, timezone, 자정, 미래 구매 오류, 빈 목록, 0 분모와 금액 문자열을 검증한다. 원천 쿼리·중복 이벤트·매출 귀속 통합 테스트는 단계 3·5·10에서 추가한다.

단계 3에서는 데이터셋의 첫 적재 `reference_at`을 고정하고 그 시점 이하의 COMPLETED 주문에서 고객 캐시를 계산한다. 취소·전액 환불·미래 주문은 제외하며 PURCHASE 이벤트는 구매 합계에 다시 더하지 않는다. CSV의 ACTIVE/CHURN_RISK/DORMANT 값은 캐시를 덮어쓰지 않는다. `tests/integration/test_imports.py`에서 중복·환불·미래 주문·원천 대조를 검증한다. 선택 기간별 대시보드 집계와 캠페인 귀속은 후속 단계다.
