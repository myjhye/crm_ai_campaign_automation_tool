# 단계 7 — 캠페인 초안과 A/B 편집

## 구현 내용

`Campaigns`에서 목표·대상·채널·A/B 카피·실험 비율을 한 폼으로 입력하고, 저장 성공 후 저장 내용 확인 영역을 연다. 입력 도중 화면을 이동시키지 않으며 서버 저장이 성공하기 전에는 확인 단계로 넘어가지 않는다. 캠페인 목록의 편집 버튼으로 다시 불러오고 같은 내용으로 새 캠페인을 작성할 수도 있다.

저장된 목록의 **삭제**는 실수 방지를 위해 같은 버튼을 두 번 눌러 확인한다. 작성 중인 DRAFT만 삭제할 수 있으며 실제 행을 지우지 않고 `archived_at`을 기록해 목록에서 제외한다. 검수·승인·감사 이력과 연결된 식별자는 유지된다.

이 단계에서 생성되는 상태는 `DRAFT`다. 대상자 수신 동의·피로도 검수, 승인과 발송은 단계 8~9에서 구현한다. 오른쪽 AI 카피 어시스턴트가 메인 폼 조건을 사용해 A/B 제목·본문·가설을 자동으로 채운다. 생성 후 직접 수정하고 기존 저장 버튼으로 저장한다. 자세한 흐름은 [AI-B 사용 안내](phase_ai_b.md)를 참고한다.

대상·제외 세그먼트는 같은 스타일의 체크박스로 선택한다. 대상은 1개만 선택하며 다른 항목을 체크하면 기존 선택이 해제된다. 제외는 여러 개 선택할 수 있고 기본은 모두 미선택인 ‘제외 없음’이다. 체크한 항목을 다시 클릭하면 해제된다. 대상과 동일한 세그먼트를 제외하는 저장은 차단한다.

## 실행

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

기존 VS Code 실행 작업도 사용할 수 있다. 데이터셋을 선택하고 Segments에서 대상 조건을 먼저 저장한 뒤 Campaigns로 이동한다. 대상·제외 세그먼트는 같은 데이터셋의 revision을 참조한다. 이후 세그먼트 원본을 수정해도 캠페인의 대상 조건은 자동 변경되지 않는다. 목록에 없는 이전 버전도 기존 캠페인에서 유지한다.

## 파일과 API

| 파일 | 역할 |
| --- | --- |
| `alembic/versions/005_campaigns.py` | 캠페인·A/B 변형·제외 세그먼트 테이블과 제약 |
| `app/models/campaigns.py` | 모델, 데이터셋 복합 FK, 상태·비율 CHECK |
| `app/schemas/campaign.py` | 입력·채널·비율·금액·시간 검증 |
| `app/repositories/campaigns.py` | 조회, 목록, 변형 갱신·제외 조건 저장 |
| `app/services/campaigns.py` | 버전 잠금·업무 규칙·감사 기록 트랜잭션 |
| `app/domain/campaigns/copy_policy.py` | 버전별 데모 카피 기준 |
| `frontend/src/features/campaigns/index.js` | 편집·목록·저장 확인·충돌 복구 화면 |

- `GET/POST /api/v1/campaigns`: 목록·생성
- `GET/PUT /api/v1/campaigns/{id}`: 상세·수정
- `GET /api/v1/campaigns/copy-policy`: 현재 카피 기준

목록·상세는 `dataset_id`로 범위를 지정한다. 수정에는 현재 `version`을 보낸다. 캠페인 행을 잠근 뒤 DRAFT·version을 확인하고, 변경·A/B 저장·감사 기록을 한 트랜잭션으로 처리한다. 실패 시 모두 롤백하며 충돌은 409다. UI는 입력을 유지하고 명시적으로 최신 내용을 불러오게 한다.

## 입력 계약

이름·목표·혜택·브랜드 톤·대상 revision·KPI·목표값·A/B 본문과 가설이 필수다. EMAIL/PUSH는 제목도 필수이며 SMS에는 제목을 저장하지 않는다. 목표값은 JSON 문자열, DB `Numeric(18,2)`로 저장한다. 비율 KPI 목표는 0~100이다.

A/B 이름은 캠페인 내 유일하며 양쪽 모두 양수 비율이어야 한다. 정수 basis point 합계 10,000을 입력 검증과 서비스 트랜잭션에서 확인한다. UI는 소수 둘째 자리까지의 백분율을 사용한다. 편집해도 변형 ID는 유지한다.

`planned_at`과 `coupon_expires_at`은 timezone 포함 시각이며 UTC로 정규화한다. 화면은 한국 시간 선택기다. 예정 시각은 참고 정보로만 보관하고 자동 예약 실행을 하지 않는다. 쿠폰 만료에 따른 실행 차단은 단계 8 검수의 책임이다.

현재 데모 카피 정책 v1:

| 채널 | 제목 | 본문 |
| --- | ---: | ---: |
| EMAIL | 120자 | 5,000자 |
| PUSH | 60자 | 300자 |
| SMS | 없음 | 500자 |

일반 텍스트만 제공하며 HTML·중괄호 개인화 변수를 거절한다. 금지 표현 기본값은 `무조건 당첨`, 필수 문구 목록은 비어 있다. 문자 수는 Python 문자열 길이 기준이며 발송사 인코딩·바이트 제한이나 법규 적합성 보장이 아니다. 정책을 버전별 상수로 관리하고 저장 시 적용 버전을 기록한다. 방문자가 정책을 변경하는 Settings UI와 영속 정책 모델은 단계 8에서 추가한다.

## 검증

실제 PostgreSQL에서 생성·재조회·수정, 변형 ID 유지, 오래된 version 거절, 다른 데이터셋 참조 차단, 비율·빈 카피·변수·날짜 오류, PUSH/SMS 저장, 감사 실패 롤백을 확인했다. 전체 백엔드 88개 테스트가 통과했다.

브라우저 테스트는 API 대역을 사용해 A/B 비율 오류, 저장 알림, SMS 제목 처리, 수정 충돌 시 입력 유지와 최신 상태 복구를 확인한다. 실제 API 테스트와 브라우저 대역 테스트를 구분한다.
