# GrowthPilot 포트폴리오 소재집 — 그로스·CRM 마케터의 업무를 어떻게 연결하는가

> 목적: 지원서, 포트폴리오 페이지, 발표, 면접 답변에서 골라 쓸 수 있도록 가능한 한 많은 설명 소재를 모았다.
> 코드·문서 확인 기준: 2026-09-26. 문구는 선택 가능한 초안이며 실제 조직의 도입 성과나 시간 절감 실측치가 아니다.

## 1. 프로젝트를 한 문장으로 설명하는 여러 방법

1. **GrowthPilot은 고객 데이터에서 타깃 선정, 캠페인 설계, 정책 검수, 모의 발송, A/B 성과 해석까지 이어지는 CRM 업무 워크스페이스다.**
2. **고객을 찾은 뒤 발송 가능한 대상인지 다시 계산하고, 결과를 다음 실험에 반영하는 과정을 하나의 흐름으로 연결했다.**
3. **마케터가 자연어로 고객 조건을 탐색하고 캠페인 문안을 검토할 수 있게 하되, 숫자와 승인 판단은 검증 가능한 서버 결과에 묶었다.**
4. **세그먼트의 ‘조회 인원’과 실제 ‘발송 가능 인원’이 다른 이유를 사유별로 보여주는 캠페인 운영 데모다.**
5. **A/B 문안 생성에서 끝나지 않고, 누가 발송 대상이 되었고 어떤 반응과 주문이 귀속되었는지까지 추적하는 포트폴리오 프로젝트다.**
6. **공개 체험용 합성 CRM 데이터를 기반으로 캠페인의 기획·검수·실행·성과·재실험 순환을 시연한다.**
7. **AI를 ‘자동 발송 버튼’이 아니라, 조건 탐색·문안 제안·성과 해석을 돕는 업무 인터페이스로 사용했다.**

가장 짧게 소개한다면: **“고객 세그먼트 발굴부터 캠페인 실험 결과까지 한 화면 흐름으로 연결한 CRM 마케팅 시뮬레이터”**.

## 2. 마케터 업무에서 겨냥한 마찰

이 문서의 ‘기존 방식’은 특정 회사의 실제 현행 프로세스를 조사한 결과가 아니라, 여러 도구·시트·사람 사이를 오가는 일반적인 비교 시나리오다. 조직별로 이미 자동화된 단계가 있을 수 있다.

| 업무 순간 | 도구가 분리돼 있을 때 반복되는 일 | GrowthPilot의 연결점 | 줄이려는 작업 |
| --- | --- | --- | --- |
| 고객 규모 확인 | 대시보드에서 수치를 보고 별도 리스트에 다시 필터 | Overview 지표와 Customers 상세 탐색 | 수치와 명단 사이의 왕복 |
| 타깃 조건 정의 | SQL 요청 또는 필터 설정을 문서로 전달 | 조건 빌더·미리보기·자연어 조회 | 조건 전달·재입력 |
| 캠페인 대상 확정 | 타깃 CSV와 실제 수신 동의를 별도로 대조 | 대상 revision 고정과 정책 검수 | 대상으로 셌지만 발송할 수 없는 고객의 뒤늦은 발견 |
| 문안 작성 | 빈 문서에서 A/B 문구를 만들고 필드에 복사 | 캠페인 폼 옆 AI 초안 → A/B 필드 채움 | 반복 입력·복사 |
| 혜택·채널 검토 | 문안과 조건을 여러 사람이 수동 확인 | 채널별 길이·혜택·정책 검증 | 명백한 형식 오류의 재검토 |
| 승인 | 검수 시점의 조건·정책 버전 기록이 흩어짐 | 검수 스냅샷·30분 유효성·버전 기반 승인 | 무엇을 승인했는지 다시 찾기 |
| 실행 | 승인 명단과 실행 명단의 상태 차이 확인 | 실행 직전 적격성 재검사 | 동의 철회·기수신 대상의 누락된 재확인 |
| 결과 집계 | 발송·오픈·클릭·구매 시트를 결합 | 같은 원장의 Campaigns·Reports·Experiments | 화면마다 다른 집계 기준 |
| A/B 해석 | 큰 숫자만 보고 임의로 승자 선언 | 표본·p값·수신거부 가드레일 | 수치 우세와 통계 판정을 혼동 |
| 다음 캠페인 | 지난 실험의 대상·문안을 다시 조합 | 근거 기반 AI 분석과 후속 초안 | 실험 결과가 다음 기획으로 이어지지 않는 단절 |

### 이 프로젝트가 단축하는 것은 무엇인가

- **기다리는 단계:** 사람이 SQL·리스트·시트를 받아 연결하던 일부 조회를 셀프서비스 미리보기로 바꾼다.
- **다시 입력하는 단계:** 저장한 세그먼트 revision을 캠페인 대상에서 참조하고, 생성 문안을 폼에 채운다.
- **검수 재작업:** 동의·연락처·중복·피로도와 문구 차단을 발송 전 사유별로 보여준다.
- **설명 작성:** 실제 성과 숫자를 구조화한 다음 AI가 허용된 사실·가설·다음 행동을 선택한다.
- **원인 추적:** 검수 시점의 규칙 결과, 승인 상태, 실행 실패 사유, A/B 이벤트와 주문 귀속을 연결한다.

**실측하지 않은 표현은 피한다.** “캠페인 제작 시간을 80% 줄였다”, “전환율을 30% 올렸다”처럼 조직에서 측정한 적 없는 성과 수치를 포트폴리오 사실로 쓰지 않는다. 대신 “몇 번의 화면 왕복을 한 흐름으로 묶었는가”, “어떤 수동 대조를 코드로 재현했는가”를 보여준다.

## 3. 전후 비교: 한 캠페인을 만드는 흐름

예시 과제: **60일 이상 구매가 없고 누적 구매액이 30만 원 이상인 고객에게 이메일 재구매 캠페인을 기획한다.**

| 순서 | 분리된 도구를 사용하는 예시 | GrowthPilot 시연 | 방문자가 확인할 결과 |
| --- | --- | --- | --- |
| 1 | 분석가에게 고객 조건과 기준일을 설명 | Segments 템플릿 또는 AI에 자연어 질문 | 조건 문장·대상 수·전체 대비 비중 |
| 2 | 쿼리 결과를 받아 CSV로 보관 | 미리보기 후 세그먼트 저장 | 이름·조건·revision·기준 시점 |
| 3 | 캠페인 도구에서 타깃 조건을 다시 설정 | 저장된 세그먼트를 대상에 체크 | 현재 revision 참조와 제외 세그먼트 선택 |
| 4 | A/B 문안과 혜택을 별도 문서에 작성 | 캠페인 설정 후 AI 전체 초안 생성 | 제목·본문·가설이 메인 폼에 입력 |
| 5 | 동의·이메일 주소·중복 발송을 따로 확인 | 정책 검수 실행 | 최초 대상, 각 제외 사유, 승인 대상 |
| 6 | 승인 요청 메일에 수치·조건을 복사 | 검수 결과를 확인하고 승인 요청·승인 | 내용/정책/데이터 버전이 맞는 승인 |
| 7 | 발송 명단을 다시 추출 | 승인 스냅샷을 상한으로 실행 직전 재검사 | 탈퇴·동의 철회 등 실행 전 제외 |
| 8 | 발송·반응·주문 데이터를 수동 결합 | 모의 발송과 결과 탭 | A/B별 발송, 이벤트, 귀속 전환·매출 |
| 9 | 보고서에 숫자를 옮기고 판정 설명 | Reports·Experiments·AI 분석 | 같은 원장의 수치, 판정 근거, 재실험 제안 |

여기서 단축 효과는 **단계 자체를 생략**하는 것이 아니다. 정책 검수와 승인은 남겨두고, 단계 사이의 데이터 이관·재설명·재확인을 줄이는 설계다. 실제 발송은 하지 않는다.

### 시연 중 말할 수 있는 짧은 해설

> “일반적인 캠페인 준비에서는 타깃을 찾은 뒤에도 연락 가능한 인원과 이미 메시지를 받은 인원을 다시 확인해야 합니다. 여기서는 세그먼트의 조회 인원과 정책 검수 후 승인 대상을 나눠 보여줍니다. 마케터는 왜 줄었는지 사유별로 보고, 통과한 버전을 승인한 뒤 결과를 같은 흐름에서 확인할 수 있습니다.”

## 4. 기능별 포트폴리오 설명 소재

### 4.1 Overview — 질문을 만드는 출발점

- 실제 고객 KPI 4개와 고객 상태 분포·행동 퍼널을 요약한다.
- 데이터가 없거나 아직 계산하지 못한 지표를 임의의 0으로 채우지 않는다.
- 기간은 한국 시간의 시작일·종료일 선택이며 서버에는 UTC 반개구간으로 전달한다.
- 데이터셋 성격과 고객·주문·이벤트 규모를 알려 시연 데이터의 맥락을 준다.
- 고객 상태 또는 퍼널 항목에서 상세 고객 탐색으로 이동할 수 있다.
- **설명 포인트:** “대시보드에서 숫자를 보는 데 그치지 않고, 왜 그런 숫자인지 확인할 고객 목록으로 내려갈 수 있게 했다.”

### 4.2 Customers — 집계에서 개별 패턴으로

- 이름·상태·연락처 표시·구매 합계·주문 수·최근 구매를 목록에서 본다.
- 이름 검색, 상태·활동·가입 기간 필터, 정렬·페이지네이션을 사용한다.
- 이벤트·구매 내역을 상세에서 확인한다.
- 합성 한국어 이름을 화면에 쓰고 개발용 시나리오 ID는 화면의 주인공으로 표시하지 않는다.
- 연락처는 마스킹하고 없는 이메일은 ‘이메일 미등록’으로 구분한다.
- **설명 포인트:** “집계값의 원천 고객 패턴을 확인하되, 연락처 원문 노출은 줄였다.”
- **주의:** 이 화면만으로 고객 개인정보 활용 동의가 완료되는 것은 아니다. 발송 적격성은 캠페인 검수에서 별도로 판단한다.

### 4.3 Segments — ‘조건이 맞는 사람’과 ‘발송 가능한 사람’의 구분

- 휴면 VIP·첫 구매 유도·재구매 유도·이탈 위험·충성 고객·이메일 반응 고객 등의 편집 가능한 템플릿을 제공한다.
- 조건은 AND/OR, 필드·연산자·값으로 표현하고 타입과 복잡도를 검증한다.
- 저장 전 고객 수·전체 대비 비중·평균 누적 구매액·선호 카테고리·이메일 오픈 기록을 본다.
- 기준 시점을 선택해 “언제 기준의 대상인가”를 확인한다.
- 저장 시 revision을 남기고 캠페인은 선택된 revision을 참조한다. 이후 세그먼트 수정이 과거 캠페인 조건을 몰래 바꾸지 않는다.
- **설명 포인트:** “타깃 규모를 미리보고 조건의 의미를 한국어로 확인한다. 단, 이 수치는 발송 적격 인원과 다르다.”
- **추가 질문:** “장바구니 이벤트는 있지만 구매 이벤트는 없는 고객”처럼 구매 주문과 행동 이벤트의 차이를 시연할 수 있다.

### 4.4 Campaigns 작성 — 기획 정보를 실행 가능한 초안으로

- 캠페인 이름·목표·주요 KPI·목표값, 대상·제외 세그먼트, EMAIL/PUSH/SMS 채널과 혜택을 입력한다.
- A/B 제목·본문·가설과 배분 비율을 한 화면에서 편집한다. 기본 배분은 50:50이다.
- 폼 우측의 AI 도구는 대상·목표·채널·혜택·말투·강조점 선택으로 전체 초안을 만든다. 결과를 메인 폼에 채우고 최종 저장은 별도 버튼으로 진행한다.
- 목표·말투·강조점에는 직접 입력 ‘기타’ 옵션이 있다.
- 같은 생성 설정의 검증된 카피는 캐시에서 재사용해 다시 모델을 호출하지 않을 수 있다. 데이터·정책·모델·프롬프트 버전이 바뀌면 키가 달라진다.
- 저장한 캠페인은 검색·상태 필터·6개 단위 목록 페이지로 관리한다. 보관 삭제는 업무 이력을 물리적으로 지우지 않는다.
- **설명 포인트:** “AI 문안은 작성 보조이고, 대상·혜택·배분과 최종 저장을 방문자가 검토한다.”
- **주의:** AI가 작성한 A/B 카피는 좋은 성과를 보장하지 않는다. 채널 길이·혜택·숫자·금지 표현 등의 형식 검증을 거친다.

### 4.5 정책 검수·승인 — 운영 리스크를 발송 전에 드러내기

- 저장된 캠페인 대상을 검수 시점에 다시 계산한다.
- 탈퇴, 채널 미동의, 연락처 없음·오류, 제외 세그먼트, 같은 캠페인 기수신, 일일 한도, 최근 7일 피로도를 점검한다.
- 한 고객이 여러 규칙에 걸릴 수 있다. 모든 사유를 기록하고, 인원 합계에는 우선 사유 하나를 사용한다.
- `최초 대상 = 우선 사유별 제외 + 승인 대상`이 맞는지 보장한다.
- 쿠폰 만료·금지 표현·필수 문구 누락·비율 오류·승인 대상 0명은 캠페인 전체 차단 사유다.
- Settings 경로에서 한도·채널별 문구 정책을 변경할 수 있다. 현재 공개 데모의 좌측 기본 메뉴에는 Settings가 보이지 않으므로 이 기능을 메인 시연의 첫 단계로 제시하지 않는다.
- 검수 기록은 30분 동안 유효하며 정책·데이터·캠페인 버전이 바뀌면 이전 검수로 승인하지 못한다.
- **설명 포인트:** “타깃 수가 500명이라는 것과 500명에게 보내도 된다는 것은 다르다. 차이를 사유별 숫자로 보이게 했다.”

### 4.6 모의 발송 — 승인한 대상과 실행한 대상의 차이

- 승인 당시 적격 스냅샷을 후보 상한으로 잡는다.
- 실행 직전에 동의 철회·탈퇴·연락처·중복·피로도를 다시 확인한다. 새로 자격을 얻은 고객을 임의로 추가하지 않는다.
- PostgreSQL 작업 큐와 worker가 A/B를 결정론적으로 배정한다.
- 재요청 멱등 키, run·고객별 unique 제약 등으로 중복 실행을 막는다.
- 발송 실패·실행 전 제외 사유, A/B별 발송·실패, 전달·오픈·클릭·전환·수신거부 인원을 볼 수 있다.
- **설명 포인트:** “승인과 발송 사이에도 고객 상태가 바뀔 수 있으므로 실행 직전 적격성을 다시 확인했다.”
- **주의:** 발송은 합성 데이터에 대한 시뮬레이션이다. 외부 이메일·푸시·SMS 제공업체로 보내지 않는다. 실제 메시지 전달률이나 실제 매출 개선을 증명하지 않는다.

### 4.7 Reports — 채널별 숫자를 한 계산 기준으로

- Campaigns 결과 탭·Experiments·Reports·CSV가 공통 성과 계산을 사용한다.
- 선택 발송 기간에 성공한 발송 고객을 cohort로 잡는다.
- 오픈·클릭·수신거부는 이벤트 중복이 있어도 고객 단위 고유 인원으로 센다.
- 주문 전 7일 이내 마지막 클릭 한 건에 완료 주문을 귀속한다.
- 취소·전액 환불 주문, 클릭 없는 주문은 기여 매출에 넣지 않는다.
- 현재 기간과 직전 동기간, 채널·세그먼트별 요약을 볼 수 있다.
- CSV는 화면과 같은 기준으로 만들고 UTF-8 BOM·수식 실행 문자열 방어를 적용한다.
- **설명 포인트:** “한 캠페인의 결과 카드와 보고서 CSV가 서로 다른 숫자를 말하지 않게 계산을 공유했다.”
- **주의:** 마지막 클릭 귀속 매출은 ‘마케팅이 없었으면 발생하지 않았을 매출’이라는 증분 효과가 아니다.

### 4.8 Experiments — 숫자상 우세와 승자 확정의 차이

- A/B 전환율 또는 클릭률을 나란히 비교하고 차이, 표본, p값, 95% 신뢰구간을 표시한다.
- 기준을 통과해 통계적으로 유의하면 A안/B안 우세를 표시한다.
- 차이가 있어도 유의하지 않으면 ‘승자 확정 불가’와 표본 확대·재검증 제안을 보여준다.
- 시연 최소 표본은 안별 30명이며, 승자 선언에는 `p < 0.05` 등이 별도로 필요하다.
- B안 수신거부율이 A안보다 1%p 넘게 높으면 승자 선언을 막는 가드레일이 있다.
- 매출 주지표의 유의성 검정은 제공하지 않아 판단 보류한다.
- 관찰 기간은 합성 데이터 시연을 위해 완료 즉시 종료되도록 설정돼 있다.
- **설명 포인트:** “A안 3.27%, B안 2.15%라도 p값이 기준을 넘으면 확정 승자로 말하지 않는다. 수치상 우세와 통계적 확신을 분리했다.”
- **주의:** 현재의 최소 표본과 즉시 관찰 종료는 실제 실험 운영에 그대로 사용하기 위한 기준이 아니다. 무발송 통제군도 없다.

### 4.9 AI 어시스턴트 — 질문을 업무 도구로 연결

- 첫 화면에 고객 현황·타깃 탐색·세그먼트 저장·채널별 비교·성과 순위 질문 22개를 분류해 제공한다.
- 최근 제한된 대화와 조회한 조건을 참고해 “이 고객에게 보낼 문구”처럼 이어지는 질문을 이해하도록 한다.
- 고객 지표·타깃·성과 숫자는 서버 도구가 계산한다. AI는 조회 종류·조건을 선택한다.
- 저장 없는 A/B 문구 추천은 세그먼트를 저장하지 않아도 사용할 수 있다. 실제 세그먼트·캠페인 저장은 확인 동작을 거친다.
- 이전 결과에 따라 짧은 후속 질문을 입력창 위에 제안한다.
- 고객 행·연락처를 모델의 조회 도구로 내보내지 않고, 허용 필드의 조건과 제한된 참조를 사용한다.
- 응답 스크롤은 새 답변의 시작을 보여주고, 이전 대화를 읽는 중이면 위치를 유지한다.
- **설명 포인트:** “자연어를 실행 권한으로 바로 연결하지 않았다. AI는 의도를 해석하고, DB 수치와 저장 여부는 서버와 사용자가 결정한다.”
- **주의:** 모든 자유 문장의 정확한 이해를 보장하지 않으며, 문구의 비수치 사실성은 검토가 필요하다.

### 4.10 AI 성과 분석 — 사실·가설·행동의 분리

- 완료 캠페인의 구조화 성과를 근거로 AI가 중요 지표 ID, 허용된 가설, 후속 행동 코드를 선택한다.
- 화면은 확인된 사실·검증이 필요한 가설·해석의 한계·다음 행동을 분리한다.
- 실제 수치는 서버가 metric ID에 연결한다. AI가 자유 문장으로 성과 숫자를 만들어 표시하는 방식이 아니다.
- 동일 조건 재실험 초안은 기존 대상·제외·혜택·A/B 문안·배분을 유지하며 방문자 확인 후 DRAFT로 저장한다.
- 완료 캠페인은 Campaigns와 Experiments의 AI 분석 탭에서 볼 수 있다.
- **설명 포인트:** “분석 카드에서 관찰 사실과 원인 가설을 따로 표시해, 상관관계를 확정 원인처럼 말하지 않게 했다.”

### 4.11 데모 데이터 — 보여줄 수 있는 사례를 설계

- 실제 고객이 아닌 합성 데이터와 결정론적 seed를 사용한다.
- 중형 샘플은 기본 생성 기준 고객 5,000명·상품 300개·주문 15,000건·이벤트 100,000건이다. 이후 완료 캠페인 시드 작업이 합성 고객을 추가할 수 있으므로, 화면의 현재 고객 수는 생성 직후 기본 수치와 다를 수 있다.
- 휴면 VIP, 신규 미구매, 이메일 미동의, 장바구니 이탈, 반복 구매, 모바일 이탈 등 시나리오를 포함한다.
- 완료 캠페인 시드는 세그먼트·채널·완료 시점을 다양하게 배치해 Reports와 비교 기능의 입력을 만든다.
- 같은 seed로 재실행해도 기존 조합을 건너뛰도록 설계했다.
- **설명 포인트:** “한두 건의 예쁜 화면만 만든 것이 아니라, 정책 제외·성공·실패·판단 보류를 재현할 수 있는 데이터 시나리오를 만들었다.”

## 5. 가장 강한 차별점 후보

원하는 지원 직무에 맞춰 두세 개만 고르면 된다.

1. **퍼널 전체 연결:** 고객 탐색부터 실험 결과까지 각 단계의 입력과 출력을 추적할 수 있다.
2. **조회 대상과 발송 대상의 분리:** 세그먼트 미리보기와 적격 검수를 다른 숫자로 다룬다.
3. **승인 당시 근거 보존:** 캠페인·세그먼트·정책·데이터 버전을 묶어 승인한다.
4. **실행 직전 재검사:** 검수 이후 생긴 동의 철회·기수신 상태를 반영한다.
5. **서버 계산을 재사용하는 AI:** 모델이 숫자를 쓰는 대신 도구 결과를 화면에 표시한다.
6. **확인 후 저장:** AI가 초안을 제안하더라도 세그먼트·캠페인을 자동으로 저장하지 않는다.
7. **실험 해석의 절제:** 유의하지 않은 수치상 우세를 승자라고 단정하지 않는다.
8. **성과 정의의 일관성:** 캠페인 화면·보고서·CSV가 같은 attribution 기준을 사용한다.
9. **시뮬레이션의 재현성:** 고객·반응·A/B 배정과 완료 캠페인 사례를 seed로 재현한다.
10. **실패 경로도 시연:** 0명, 검수 차단, 409 충돌, 중복 실행, 판단 보류를 설명 가능한 상태로 보여준다.

> “제가 집중한 문제는 마케터가 타깃을 찾은 뒤에도 캠페인 도구에서 조건을 다시 만들고, 발송 가능한 인원을 다시 세고, 결과를 별도 보고서로 옮겨야 하는 단절입니다. GrowthPilot에서는 세그먼트 조건과 revision을 캠페인 대상으로 연결하고, 동의·연락처·기수신·피로도 검수를 사유별로 보여줍니다. 승인 후에는 외부 메시지 없이 합성 고객에게 모의 발송을 실행하며, A/B 반응과 클릭 귀속 매출을 동일한 계산 기준으로 보고합니다. AI는 고객 조건과 문안을 제안하지만 숫자를 임의로 만들거나 확인 없이 업무 데이터를 저장하지 않습니다. 실제 운영 성과를 주장하기보다, 어떤 업무 단계를 연결하고 어떤 오류를 예방했는지 보여주는 포트폴리오입니다.”

## 8. 화면 시연 스토리보드

### A안: CRM 운영 흐름, 약 4~6분 구성 예시

| 장면 | 화면에서 할 일 | 말할 핵심 |
| --- | --- | --- |
| 1 | Overview에서 데이터 규모·기간 확인 | 합성 데이터와 조회 기준을 먼저 밝힘 |
| 2 | Segments에서 휴면 VIP 미리보기·저장 | 대상 조건을 사람이 읽을 수 있는 문장과 수로 확인 |
| 3 | Campaigns 작성에서 세그먼트 체크·AI 전체 초안 | 저장된 대상을 재입력 없이 연결, 문안은 검토 가능 |
| 4 | 검수·승인 탭에서 제외 사유 펼침 | 조회 대상과 발송 가능한 대상의 차이 |
| 5 | 승인 뒤 모의 발송 | 승인 시점과 실행 시점의 고객 상태 차이 재검사 |
| 6 | 결과·Experiments에서 A/B 판정 | 숫자상 우세와 확정 가능한 결과를 구분 |
| 7 | AI 분석에서 가설·다음 행동 | 실험 결과를 다음 기획으로 연결 |

### B안: AI 활용, 약 3~4분 구성 예시

1. AI 첫 화면에서 ‘장바구니 이벤트는 있지만 구매 이벤트는 없는 고객’을 질문한다.
2. 고객 수와 조건 설명이 서버 결과인지 확인한다.
3. “이 고객에게 보낼 A/B 문구 추천”을 입력해 저장 없는 문안 두 안을 보여준다.
4. “더 짧게 다듬어줘”로 최근 대화 문맥을 보여준다.
5. 실제 캠페인 생성이 필요한 경우 저장된 세그먼트를 선택하고 Campaigns의 전체 초안 도구로 이동한다.
6. 완료 캠페인 비교에서 “전환율 상위 3개” → “위 캠페인을 클릭률 순으로”를 시연한다.
7. 마지막에 어떤 답이 DB 계산이고 어떤 답이 AI 문장인지 분명히 말한다.

### C안: 분석 직무, 약 3~4분 구성 예시

1. Overview의 활성·신규 고객과 행동 퍼널을 본다.
2. Customers로 내려가 가입일·상태·활동 필터와 정렬을 보여준다.
3. Reports에서 발송 기간별 성과와 CSV를 연다.
4. Experiments에서 숫자상 A안 우세지만 승자 확정 불가인 사례를 보여준다.
5. 통계 상세의 표본·p값·신뢰구간과 무발송 통제군 부재를 짚는다.

## 9. 면접에서 받을 수 있는 질문과 답변 뼈대

| 질문 | 답변 방향 |
| --- | --- |
| “왜 AI가 바로 발송하지 않나요?” | 고객 접촉은 되돌릴 수 없으므로 AI 제안→서버 검증→방문자 승인→실행을 분리했다. 데모는 실제 발송을 하지 않는다. |
| “세그먼트 500명인데 승인 대상은 왜 적나요?” | 조건에 맞는 고객과 채널 동의·연락처·중복·피로도 기준을 통과한 고객이 다르다. 사유별로 확인 가능하다. |
| “검수했으면 실행 전에 또 확인할 필요가 있나요?” | 승인 후 동의 철회나 기수신 상태가 바뀔 수 있다. 승인 스냅샷은 상한이며 실행 시점에 자격을 다시 검사한다. |
| “AI가 잘못된 숫자를 말하면?” | 지표·매출은 DB 서비스 결과를 직접 렌더링한다. 조건·도구 인자는 다시 검증한다. 성과 해석은 허용된 metric ID에 서버 수치를 연결한다. |
| “AI가 없는 상태에서도 되나요?” | Customers·Segments·Campaigns·검수·모의 발송·Reports 수동 흐름은 별도 서비스로 동작한다. |
| “같은 세그먼트가 나중에 바뀌면?” | 캠페인은 선택된 revision을 참조한다. 이후 수정이 기작성 캠페인 대상을 자동으로 바꾸지 않는다. |
| “B안 수치가 높으면 바로 승자인가요?” | 표본·유의성·수신거부 가드레일을 함께 본다. 통제군이 없어 무발송 대비 증분 효과를 말할 수 없다. |
| “매출 귀속은 어떻게 정했나요?” | 완료 주문 전 7일 이내 마지막 클릭 하나에 귀속한다. 관측 기준이며 인과 효과가 아니다. |
| “실제 서비스에 도입하려면?” | 계정·역할 권한, 채널 공급업체, 법규 검토, 운영용 관찰 기간·표본 설계, 실사용 데이터 보호, 배포·모니터링을 추가해야 한다. |
| “포트폴리오에서 가장 중요한 설계 판단은?” | AI 자동화의 편의와 고객 접촉의 책임을 분리하고, 검수 근거·버전·실행 결과를 연결한 점이다. |

## 10. ‘시간을 줄였다’를 증명하려면 무엇을 측정할까

현재 프로젝트에는 실제 팀의 전후 작업 시간 데이터가 없다. 아래는 **후속 사용자 테스트 설계안**이다.

| 지표 | 시작·끝 정의 | 비교 방법 |
| --- | --- | --- |
| 첫 대상 초안까지 시간 | 요구 조건 수령 → 대상 수와 조건 문장 확인 | 시트/분리 도구 흐름 vs GrowthPilot 동일 과제 |
| 캠페인 DRAFT까지 시간 | 조건 수령 → 대상·혜택·A/B 문안 저장 | 같은 숙련도 참가자에게 순서 교차 실험 |
| 발송 전 오류 발견 수 | 잘못된 동의·연락처·중복·정책 문구 중 실행 전 발견 건수 | 공통 오류가 삽입된 동일 시나리오 |
| 재입력 횟수 | 동일 대상 조건을 다른 도구에 다시 입력한 횟수 | 화면 기록으로 계수 |
| 화면·도구 왕복 | 필터→CSV→캠페인→보고서 전환 횟수 | 업무 로그와 화면 녹화 |
| 검수 결과 이해도 | 최초 대상·제외·승인 대상의 관계를 설명할 수 있는가 | 동일 질문의 정답률 |
| 성과 해석 정확도 | 유의하지 않은 결과를 승자로 잘못 선언했는가 | 시나리오별 판정 문항 |
| 후속 실험 착수까지 시간 | 결과 확인 → 수정 가능한 후속 DRAFT | 같은 결과 입력으로 비교 |

작업자, 데이터 규모, 과제, 오류 시나리오를 맞추고 각 참가자의 사전 숙련도를 기록해야 한다. 실제 측정 뒤에만 절감률을 계산한다. 예시 수치를 도표에 넣을 경우 **가상 예시**라고 명확히 표시한다.

## 11. ‘AI를 썼다’보다 강하게 설명할 내용

- **도구 선택과 계산을 분리했다:** 모델은 질문 의도·조건을 고르고 계산은 기존 서비스가 한다.
- **저장 없는 추천 경로를 따로 뒀다:** 아이디어 요청은 업무 리소스 생성으로 이어지지 않는다.
- **저장 제안은 확인을 거친다:** 제안 hash·만료·버전과 트랜잭션으로 적용 시점을 제한한다.
- **최근 대화는 제한적으로만 사용한다:** 후속 질문의 맥락은 보존하되 고객 행·연락처와 무제한 대화 전문을 모델에 싣지 않는다.
- **출력 오류를 다룬다:** 세그먼트 DSL 타입 검사, 형식 오류 시 제한된 재생성, 카피 혜택·숫자·채널 검증을 적용한다.
- **모의·실제 모델을 구분한다:** mock이 모든 자유 문장을 이해한다고 주장하지 않는다.
- **LLM 지표 해석의 범위를 제한한다:** AI 성과 분석은 서버 제공 사실, 허용 가설, 허용 행동을 조합한다.

## 12. 제품 한계와 정직한 설명

1. **공개 체험 공간이다.** 로그인·역할별 승인 권한 없이 방문자가 같은 합성 데이터에 접근한다. 변경 내용은 공유될 수 있다.
2. **실제 고객 데이터가 아니다.** 합성 이름·연락처·주문·반응 시나리오다. 실제 전환 성과를 입증하지 않는다.
3. **실제 발송이 아니다.** 외부 채널 API로 고객에게 이메일·푸시·문자를 보내지 않는다.
4. **시뮬레이션 반응은 확률과 seed에 의존한다.** 실제 고객 행동 예측 모델의 정확도 근거가 아니다.
5. **A/B 판단 설정은 시연 친화적이다.** 안별 최소 표본 30명과 즉시 관찰 종료를 실무 실험 설계 기준으로 제시하지 않는다.
6. **무발송 통제군이 없다.** A/B 발송안 차이는 볼 수 있으나 CRM 캠페인의 증분 효과는 측정하지 못한다.
7. **귀속 매출은 규칙 기반이다.** 마지막 클릭 7일 규칙의 관측치이며 인과적 기여액이 아니다.
8. **카피 정책 검증은 법적 검토가 아니다.** 금지 표현·문자 길이·입력 혜택의 일관성을 확인하지만 실제 광고·수신 관련 법규 적합성을 보장하지 않는다.
9. **AI의 모든 문장을 검증하지는 못한다.** 수치·도구·일부 카피 조건을 제한해도 비수치 사실·톤은 사람이 확인해야 한다.
10. **현재 기본 메뉴는 핵심 시연 위주다.** Data & Integrations와 Settings 경로는 코드에 있지만 좌측 공개 메뉴에서 제외돼 있다.
11. **완전한 배포 단계는 별도다.** 현재 README는 로컬 FastAPI·Docker PostgreSQL·worker 실행을 설명한다. 운영 보안·모니터링·실사용자 권한 모델을 완성한 서비스라고 말하지 않는다.

이 한계를 먼저 제시하면 “실제 CRM 운영 시스템을 만들었다”는 과장 대신, **업무 설계·데이터 정의·예외 처리의 사고 과정**을 설명할 수 있다.
