# 공개 데모의 데이터셋 선택

`003c` 마이그레이션은 데이터셋에 `purpose=ANALYSIS|SYSTEM`을 추가한다. 기존 데이터는 ANALYSIS이며, 이름이 정확히 `Worker diagnostic`인 기존 데이터만 SYSTEM으로 분류한다. 이름·버전·사용자 편집 내용은 변경하지 않는다. worker 점검 스크립트도 앞으로 SYSTEM으로 생성한다.

방문자 데이터셋 목록과 상세·수정 API는 ANALYSIS만 취급한다. SYSTEM UUID를 직접 지정하면 404다. 공개 API에 전체 노출 옵션을 두지 않으며 시스템 점검은 기존 운영 스크립트와 DB에서 확인한다. 이 분류는 사용자 인증이나 테넌트 권한 체계가 아니다.

목록은 전체 ANALYSIS 중 고객이 존재하는 데이터를 먼저 정렬하고, 같은 그룹에서는 생성 시각과 ID 내림차순으로 정렬한 후 페이지를 나눈다. 따라서 첫 100개 밖에 있던 오래된 샘플도 빈 데이터보다 먼저 선택된다. URL에 분석용 UUID가 있으면 그 선택을 유지한다. 없는 UUID나 시스템 UUID는 오류와 다시 선택 버튼을 보여주며 다른 데이터로 몰래 바꾸지 않는다.

목록·상세·생성·수정 응답에 `purpose`, `customer_count`, `order_count`, `event_count`를 제공한다. 세 원천 테이블을 각각 데이터셋별로 집계하여 조인으로 인한 중복과 행별 추가 쿼리를 피한다. 수치는 기간 필터와 무관한 전체 적재 건수다. 주문은 상태와 관계없이 원천 행을 세므로 대시보드의 완료 주문 지표와 구분한다.

Overview와 Data 카드는 실제 건수와 한국어 데이터 성격을 표시한다. 모두 0이면 빈 데이터셋이라고 안내한다. 분석용 데이터가 하나도 없으면 “체험용 샘플을 만드시겠어요?” 안내와 데이터 관리 이동을 제공한다. 이 안내가 샘플을 자동 생성하지는 않는다. 샘플 생성은 기존 `scripts.seed_demo` 실행 경로를 사용한다.

새 샘플 이름은 `체험용 확장 샘플 (고객 300명)` 또는 `체험용 전체 샘플`이다. seed·기준 시점·크기·dataset key를 이용하는 내부 UUID 및 재실행 규칙은 유지한다. 기존 샘플 이름과 데이터는 자동 변경하지 않는다. generator v2를 실행하면 정책 검수 사례가 확장된 새 데이터셋을 만든다.

적용 명령: 프로젝트 루트에서 `.\.venv\Scripts\python.exe -m alembic upgrade head`. API를 재시작하고 브라우저를 새로고침한다. 기존 주소에 시스템 UUID가 남아 있다면 **데이터셋 다시 선택**을 누른다.

검증은 PostgreSQL에서 기존 이름 보존·진단 분류·100개 초과 목록의 기본 선택·SYSTEM 조회/수정 차단을 확인하고, Chromium에서 실제 건수 카드·빈 진입·잘못된 UUID 복구를 확인한다.
